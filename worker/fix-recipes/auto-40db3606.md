# auto-40db3606
## Diagnosis
The LLM schema generator emits a `resource_collected` trigger whose `resource` field may carry extraneous whitespace (e.g. `"Gold "`). `normalizeTrigger` inside `_repairSchema` calls `hasNamedRef(t.resource)` — which trims only for the truthiness check — but never writes the trimmed value back to `t.resource`. The `GLOBAL_COUNTER_RE` regex in `validate-schema.cjs` uses `^…$` anchors and therefore fails to match `"Gold "`, producing the validation error. Because `_repairSchemaValidationErrors` has no handler for the `resource_collected` reference pattern, there is no deterministic repair path and all retries fail identically.

## Root Cause
`engine/stages/codegen-schema.cjs:1579-1582` — `normalizeTrigger` does not trim `t.resource` before storing, and `engine/stages/codegen-schema.cjs:1704-1794` (`_repairSchemaValidationErrors`) has no case for `"Phase X trigger resource_collected references non-existent resource: Y"`.

## Fix

### Change 1 — `engine/stages/codegen-schema.cjs` line 1579 (normalizeTrigger, trim resource name)
