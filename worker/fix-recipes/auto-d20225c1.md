# auto-d20225c1

## Diagnosis
The schema-generation sub-stage of `codegen` spawns the Claude CLI via `runCodexText` (claude-print backend). The worker's proxy URL (`127.0.0.1:7890`) is hardcoded in `codex-code-coder.js` and is only injected when `HTTPS_PROXY` is absent from `process.env` — it is never declared in either `.env` file, making it invisible and unconfigurable. When the local proxy process is down, the Claude CLI immediately prints `API Error: Unable to connect to API (ECONNRESET)` to stdout; the codex-exec fallback shares the same proxy route so it fails identically. All three inner retries in `generateSchemaFromSpecs` fire with zero delay, exhausting the retry budget in milliseconds against a downed proxy, then the outer pipeline stage-retry does the same — three tasks, three failures.

## Root Cause
`worker/codex-code-coder.js:643–648` — proxy guard only injects `HTTPS_PROXY=http://127.0.0.1:7890` when the variable is absent; no `.env` declaration makes the value invisible/unconfigurable. Compound: `engine/stages/codegen-schema.cjs:119–125` — retry loop has no backoff delay, so all retries hit the downed proxy in rapid succession.

## Fix

### 1. `.env` — declare HTTPS_PROXY explicitly (makes it configurable without source edits)
