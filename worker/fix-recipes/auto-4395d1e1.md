## Diagnosis
When CUA completes 0 phases for 2 consecutive rounds the `noPhasesCompleted` fallback in `_buildStuckDiagnosis` correctly classifies `rootCause = 'visual_freeze'`, but the ACTION REQUIRED text fed to the recode LLM is drawn from `rootCauseAdvice['visual_freeze']` which describes *batch-firing phases* — a completely different failure mode. The recode therefore applies gating/slow-down fixes instead of initialization fixes, the second CUA round still sees 0 phases, and the FATAL fires. Because the error is classified FATAL the fix-loop aborts with no preserved context, and worker-level task retries repeat the same cycle identically.

## Root Cause
`engine/stages/cua-verify.cjs:108–113` — `rootCauseAdvice.visual_freeze` is generic to the batch-firing case; when `stuckPhaseId === '(none completed)'` the advice is semantically wrong and actively misdirects the recode LLM away from initialization/startup bugs.

## Fix
In `_buildStuckDiagnosis`, extract `actionAdvice` into a local variable before building `detail`, and override it for the never-started sub-case. Also fix the `isProgressing` guard that prevents 0→1 phase progress from being recognised (secondary, same function).
