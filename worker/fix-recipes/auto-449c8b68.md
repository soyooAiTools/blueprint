# auto-449c8b68

## Diagnosis
`method-check` repeatedly failed with `assembly-state-owner-mismatch` when generated partials wrote state owned by another assembly module, such as a resource/UI partial mutating a flow-owned `EntityState` field.

The retry loop regenerated similar cross-owner writes, so the same contract blocker returned across tasks.

## Root Cause
`autoRepairAssemblyModuleOwnerMismatch()` handled missing slot markers, but there was no equivalent deterministic repair for state ownership drift reported by `engine/assembly-plan-contracts.cjs`.

## Fix
Add `autoRepairAssemblyStateOwnerMismatch(ctx)`:

- call `detectAssemblyContractViolations(ctx)`
- for each `assembly-state-owner-mismatch`, inspect the reported violating files
- remove generic cross-owner state mutations
- rewrite direct `gold` mutations to the owner API (`AddResource(GFM_ResourceIds.Gold, ...)` and `UpdateResourceUI()`)

The contract scanner now ignores helper libraries outside assembly owner files so canonical utility classes are not flagged as owner drift.
