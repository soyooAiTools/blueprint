## Diagnosis
`cua-verify` uses a wall-clock pre-recode guard (`MAX_CUA_TOTAL_MS - RECODE_BUFFER_MS`) at two locations (round-entry check line 325 and pre-recode check line 767). The guard threshold is computed at module load time. When `.env` carried `RECODE_BUFFER_MS=900000` (15 min) and the code read from `process.env`, the threshold was `75 - 15 = 60 min`, causing any CUA run that completed a round after 60 min to be killed prematurely. Tasks finishing at 64 min had 11 min remaining — well above the 12 min actually needed for recode+rebuild — but were still aborted. The code was subsequently patched to hardcode 12 min (line 220) and ignore the env var, but both `.env` files still carry the stale `RECODE_BUFFER_MS=720000` entry, triggering a startup warning on every process launch and leaving a latent regression risk if the hardcoding is ever reverted.

## Root Cause
`engine/stages/cua-verify.cjs:220` — `RECODE_BUFFER_MS` was previously read from `process.env.RECODE_BUFFER_MS` (= 900,000 ms / 15 min), reducing the effective CUA window to 60 min and prematurely aborting runs that completed at 64 min. The code fix (hardcoding 12 min) is now in place, but the stale env entries remain.
