## Diagnosis
When the doubao LLM returns a truncated response (JSON cut off before closing braces), `parseSimplifyResponse` calls `extractFirstBalancedJsonObject` which correctly returns `null` for unclosed JSON. The `|| raw` fallback re-instates the broken string, and `JSON.parse` throws `Unexpected end of JSON input`. The catch block repeats identical operations — it never structurally closes the open braces — so all 3 retries in `callLLMSimplify` fail with the same error and the stage aborts.

## Root Cause
`engine/stages/complexity-gate.cjs:244-251` — second-pass repair in the `parseSimplifyResponse` catch block uses `extractFirstBalancedJsonObject(repaired) || repaired`, which produces the same unclosed JSON as the first pass. No step ever appends the missing closing `}` / `]` characters needed to make a truncated stream parseable.

### 1. Add `repairTruncatedJson` helper (insert after `extractFirstBalancedJsonObject`, ~line 284)
