# auto-8e4115f8

## Diagnosis
When `fidelity-contract-synthesize` silently skips synthesis (source HTML missing required `PHASES[]`, `ENTITY_STYLE`, or `SCENE_CONFIG` top-level literals), it leaves `ctx.blueprint.fidelityContract` unset. The old `resolveFieldDiffTemplate()` contained a hard-coded fallback: `var contractPath = ctx.fidelityContractPath || DEFAULT_CONTRACT_PATH`, which pointed to the space-ranger v0.5 delivery fixture (`work/task25-sam-delivery-verify/…/fidelityContract.json`). That fixture declares ~34 space-ranger-specific entities (Player, OxygenShop, GoldMine, IceShip, etc.) that are entirely absent from any non-space-ranger Luna build, generating 34 blocking `entity-missing` field diffs and ~97 % pixel divergence on every retry. Because `canRetry: false`, the task is permanently blocked after the first attempt — all 5 observed retries hit the same deterministic false-positive gate.

## Root Cause
`engine/stages/fidelity-source-diff.cjs` — two co-located gaps:

1. **`resolveFieldDiffTemplate()` (pre-fix, ~line 553)** — used `ctx.fidelityContractPath || DEFAULT_CONTRACT_PATH` which silently loaded the space-ranger fixture for every task where synthesis was skipped.
2. **`canSkip()` (pre-fix, ~line 195)** — returned `false` (execute proceeds) for any task with `sourceHtmlPath` set, regardless of whether a task-specific contract existed. Combined with gap 1, execute() always ran with the wrong contract.

## Fix
Both changes are already applied in the current file under `// auto-8e4115f8` annotations. The recipe documents them for deploy/audit confirmation.
