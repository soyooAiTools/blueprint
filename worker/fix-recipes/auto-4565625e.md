## Diagnosis
The LLM spec extractor generates entity references in camelCase (e.g. `"forgeWorkshop"`) while `blueprint.entities` stores them in PascalCase (e.g. `"ForgeWorkshop"`). A case-insensitive fallback map (`entityLowerToCanonical`) was added on 2026-04-16 to auto-correct this in place. However, the map stores the raw, un-trimmed `e.name` as the canonical *value* while correctly trimming the *key*. This means any blueprint entity whose name carries invisible trailing/leading whitespace (a known LLM serialization artifact) produces a dirty canonical value that is written back to `ent.name`, silently corrupting the spec for downstream codegen even when no validation error is thrown.
