# auto-1b581a74
## Diagnosis
`verifyPublicPreviewProgress` in `upload.cjs` starts its 70-second deadline clock immediately after `page.goto()` completes. Unity WebGL requires 10–25 s of async WASM compilation and engine init before it writes `window.__gameState`, so the deadline expires before the property is ever set. This yields `reason: "public-preview-no-game-state"` on every attempt, burning all three upload retries. The `runtime-contract` stage (which already validated the same build) avoids this by calling `page.waitForFunction(!!window.__gameState, { timeout: 20000 })` before starting its own sampling loop; `upload.cjs` has no equivalent guard.

## Root Cause
`engine/stages/upload.cjs` — `verifyPublicPreviewProgress` started sampling immediately after `page.goto()` and treated absent `__gameState` as no progress.

## Fix

1. Wait for `window.__gameState` or `window.__getGameState()` before starting the preview progress deadline.
2. Keep a separate `PUBLIC_PREVIEW_GAME_STATE_INIT_MS` timeout so engine init failures are reported as init failures, not phase no-progress failures.
3. Only report `done` after the bare public preview has advanced through the first few spec phases.
4. On resume after a public-preview upload failure, invalidate checkpoints from `compile` onward so the worker rebuilds the preview HTML instead of reusing stale artifacts.

## Verification

- `node -c engine/stages/upload.cjs`
- Direct `_verifyPublicPreviewProgress()` against the public URL advances from `init` to a later phase and reaches the target completed count.
