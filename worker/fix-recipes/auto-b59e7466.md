# auto-b59e7466

## Diagnosis
`duplicate-object-fields` could become a false positive when two different classes declared the same field name, for example `GameFlowManagerMain.target` and `Helper.target`.

The detector counted depth-1 field declarations globally across aggregated code, while the repair only removed duplicates within the same class. That mismatch caused retries that never changed the flagged code.

## Root Cause
`collectTopLevelFieldNames()` did not track the current class, so `detectDuplicateObjectFields()` treated cross-class same-name fields as duplicates.

## Fix
Make duplicate object-field detection class-aware:

- track `currentClass` and class brace depth while scanning
- count top-level object fields per class
- report duplicates only when the same class declares the same object-like field more than once
