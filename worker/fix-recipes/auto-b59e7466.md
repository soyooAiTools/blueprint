# auto-b59e7466

## Diagnosis
`autoRepairDuplicateObjectFields` (and its twin `autoRepairDuplicateSimpleFields`) each
contain an inner `removeDuplicatesFromCode` closure that uses **hardcoded** `depth === 0`
for class-declaration detection and `depth === 1` for field matching. When the generated
C# partial files wrap `GameFlowManagerMain` inside a `namespace` block the class is at
depth 1 and its fields are at depth 2 — neither condition ever fires, so the repair is a
silent no-op. The detection function `detectDuplicateObjectFields` (via
`collectTopLevelFieldNames`) correctly uses **relative** `classDepth + 1` depth and always
finds the duplicates. Every pipeline run therefore hits: repair runs (returns `false`) →
`detectContractViolations` fires `duplicate-object-fields` → `invalidateCodegenCheckpoint`
→ codegen retry → AI regenerates the same namespace-wrapped pattern → 9 retries across 5
tasks.

## Root Cause
`engine/stages/method-check.cjs`

- **`autoRepairDuplicateObjectFields` → `removeDuplicatesFromCode`** — lines ~1162–1188
  - Class detection: `if (depth === 0)` — **should be** `if (!currentClass)`
  - Field matching: `depth === 1` — **should be** `currentClass && depth === classDepth + 1`
  - Class reset:    `if (depth === 0 && closes > 0)` — **should be** `if (currentClass && depth <= classDepth && closes > 0)`

- **`autoRepairDuplicateSimpleFields` → `removeDuplicatesFromCode`** — lines ~1100–1125
  - Identical structural bug (same three wrong expressions).

## Fix
Track `classDepth` alongside `currentClass` in both `removeDuplicatesFromCode` closures
so depth checks are relative to the class body, not the file:

- On class-declaration match, capture `classDepth = depth` and stop matching further
  class declarations until the current class closes (`if (!currentClass)`).
- Field-matching guard becomes `currentClass && depth === classDepth + 1` so fields are
  recognized regardless of whether the class is at file root or wrapped in a namespace.
- Class reset becomes `currentClass && depth <= classDepth && closes > 0` so the
  closing brace at the correct relative depth clears the tracked class.

This mirrors the pattern already used by `collectTopLevelFieldNames` (the detection
side) so detect and repair operate on the same shape. See `engine/stages/method-check.cjs`
lines 1085–1147 (`autoRepairDuplicateSimpleFields`) and 1149–1209
(`autoRepairDuplicateObjectFields`) for the applied fix.
