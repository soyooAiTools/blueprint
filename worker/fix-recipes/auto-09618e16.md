## Diagnosis
The `review` stage enforces a phase coverage gate **after** the fix-loop resolves (`loop.run(ctx).then(...)`). When the LLM reviewer (codex-reviewer) returns `passed: true` for code that calls `AddCompletedPhase("phase1")` instead of the exact spec phaseId `"initialCollectSpaceJunk"`, the fix-loop exits with `done: true` in round ≤ 6. Control then reaches the post-loop gate which runs the same 3-level fuzzy matching, finds 0/11 (0%) coverage, and throws — but with **zero retries remaining** because the loop has already exhausted. The result is a hard pipeline failure on the first (and only) time coverage is checked against the spec.

## Root Cause
`engine/stages/review.cjs:558` — the `throw new Error('Phase coverage too low: ...')` at the post-loop gate is the only location where spec phaseId coverage is enforced; there is no equivalent guard **inside** the fix-loop `attempt()` function to intercept the failure while retries are still available.

## Fix
Insert a phase coverage pre-check block inside the `attempt` function, immediately after the `staticCheck` block and before the LLM reviewer invocation (i.e., after the closing `}` of `if (!preCheck.passed) { ... }` and before `if (!reviewPromise) { if (USE_CODEX_REVIEW && ...`).
