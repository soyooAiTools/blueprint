# auto-c4693156
## Diagnosis
The schema-generation LLM occasionally writes abbreviated or un-capitalised entity names inside trigger objects (e.g. `"entity": "weapon"` instead of `"entity": "Weapon"`). The `_repairSchema / normalizeTrigger` pass only fills in a fallback when `trigger.entity` is **absent**; it does not correct a present-but-wrong name. The subsequent `validateSemantics → validateTriggerRefs` call then appends an error of the form `Phase <id> trigger entity_state_reached references non-existent entity: weapon`. The `_repairSchemaValidationErrors` function has handlers for `showEntities`, `hideEntities`, and the last-phase CTA gate, but **no handler for trigger entity reference errors**, so the error is not repaired and `codegen-schema` throws `Schema validation failed: …`, burning all three retries with the identical prompt.

## Root Cause
`engine/stages/codegen-schema.cjs:_repairSchemaValidationErrors` (~line 1895)
Error emitted by `adapters/schema/validate-schema.cjs:validateTriggerRefs` (line 86):
`errors.push('Phase ' + phaseId + ' trigger ' + trigger.type + ' references non-existent entity: ' + trigger.entity)`

The for-loop in `_repairSchemaValidationErrors` iterates the error strings and has `continue`-based handlers for every known class **except** this trigger-entity pattern, so the unmatched error falls through and `repaired` stays at 0, causing the final `throw`.
