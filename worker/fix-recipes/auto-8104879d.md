## Diagnosis
The LLM schema generator frequently emits `resource_collected` triggers whose `.resource` field names a game entity (e.g. `IcePile`) rather than an entry in `schema.resources[]`. The semantic validator (`validateTriggerRefs`) correctly flags this, but `_repairSchemaValidationErrors` — the designed deterministic repair extension point — has no branch for the pattern `Phase <X> trigger resource_collected references non-existent resource: <Y>`. The error survives both validation passes, the stage throws, and the `canRetry:true` codegen stage burns its full retry budget (2× observed) re-generating a schema that will fail in the same way.

## Root Cause
`engine/stages/codegen-schema.cjs` — `_repairSchemaValidationErrors` function, line **1823** (start of the error-dispatch loop). No `m = err.match(...)` branch handles `resource_collected references non-existent resource`.

Secondary contributor: `validate-schema.cjs:70` — `GLOBAL_COUNTER_RE` exempts `Gold|Score|…` but not domain-specific collectible names like `IcePile`, which are entity names the LLM legitimately intends as resources.
