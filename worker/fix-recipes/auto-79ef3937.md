## Diagnosis
When Claude Code CLI exits with code 1 and no `.cs` file is modified, `runClaudeCode` builds its `.error` field as `stderr || 'Exit code N'`. When `stderr` is empty (common when CC CLI writes its failure reason to stdout under `--output-format text`), the error collapses to the static string `"Exit code 1"` — identical across every retry round. The `fix-loop` circuit breaker in `engine/fix-loop.cjs` compares the first 120 characters of the classified reason; because the string never changes, `sameErrorStreak` reaches the threshold of 3 on the third round and aborts with "fix-loop not converging", discarding the remaining round budget and providing no actionable diagnostic.

## Root Cause
`worker/claude-code-coder.js:475` — the ternary branch for `code !== 0 && !fileActuallyModified && stderr empty` uses only `stderr || \`Exit code ${code}\``, silently dropping all stdout content (which may carry CC's actual failure message).
