# AI Storyboard HTML System Design

## Purpose

The AI storyboard flow turns static customer material into a playable
storyboard2html source file. The source HTML is reviewed by the user first; only
after the user confirms it does the project enter the Blueprint/WebGL build
pipeline.

This is the current standard path:

```text
static references
  -> evidence-ir.json
  -> storyboard-ai.json
  -> storyboard2html-input.json
  -> generated.html
  -> sourceHtmlPath approval
  -> SourceIR / Blueprint / WebGL
```

The older PDF/customer-storyboard package remains as a development utility, but
it is not exposed in the frontend and is not the standard handoff path.

## Frontend Flow

1. Create a project. Project creation does not accept files.
2. Open the project storyboard page.
3. Upload one or more static reference files.
4. Click `开始解析`.
5. Review the generated HTML preview.
6. Click `确认预览，继续生成 WebGL`.
7. The frontend stores `sourceHtmlPath`, clears stale derived storyboard state,
   and submits the project to the build queue.

The manual blueprint editor is no longer the normal entry point for new projects.
Top-bar submission is blocked until a source HTML has been confirmed.

## Supported Inputs

Supported static reference formats:

- PDF
- DOC / DOCX
- XLS / XLSX
- CSV
- PNG / JPG / JPEG

Each uploaded file is limited to 20 MB. The frontend and package API both
enforce this limit.

Unsupported in this automated flow:

- HTML / HTM playable references
- MP4 / MOV / WEBM / GIF / AVI / MKV dynamic media

When customers provide playable HTML or video and ask for a faithful clone, the
case should be handled manually first. The manual operator should provide static
screenshots, written phase steps, or a cleaned source HTML before entering the
automated flow.

## Phase Rules

- Runtime/customer phases must stay in the 10-13 range.
- The planner should merge excessive frames by action intent.
- The planner should expand short material only when distinct visible actions,
  resources, enemies, upgrades, or CTA steps are present.
- Non-final phases must not use CTA/click-to-advance semantics.
- The final phase must close with CTA or a CTA-ready state.
- Consecutive phases must not share the same primary gameplay target unless the
  action semantics visibly differ.
- Timer-only phases are disallowed unless the source clearly describes a
  visual-only beat.

## Artifacts

The package endpoint writes a self-contained job directory under
`server-data/storyboard-html-packages/<jobId>/package/`:

```text
generated.html                  # user-reviewed storyboard2html source
storyboard2html-input.json      # structured input bundle for generation
source-ir-preflight.json        # SourceIR readiness check
storyboard-ai.json              # planned 10-13 phase storyboard
evidence-ir.json                # extracted static evidence
audit-report.json               # diagnostics and confidence
storyboard2html-generate.log    # generator log
```

The API response includes both public URLs and filesystem paths. `paths.html` is
the value persisted as `sourceHtmlPath` when the user confirms the preview.

## Current Entry Points

```bash
cd /opt/blueprint-editor

# Build an HTML package from static references.
node scripts/storyboard-html-package.cjs --out-dir /tmp/storyboard-html \
  --project-name "Project" input.pdf notes.docx table.xlsx reference.png

# Deterministic test mode, used by automated tests.
node scripts/storyboard-html-package.cjs --out-dir /tmp/storyboard-html \
  --generation-mode deterministic input.csv

# Frontend/API endpoint.
```

## Legacy Boundaries

`/api/projects/:id/parse-and-blueprint`, `/convert-to-v4`, and the customer PDF
package endpoints are legacy or utility surfaces. They may remain available for
compatibility and developer diagnostics, but new frontend work should not call
them. The standard project submission path is source HTML first.

`parse-and-blueprint` must not be treated as authoritative when it conflicts
with the blueprint skill path. The authoritative chain is:

```text
generated.html -> SourceIR -> Blueprint/GameSchema -> Luna/WebGL
```

## Deployment Notes

- Frontend build output is generated by `cd frontend && npm run build`.
- Runtime package directories under `server-data/storyboard-html-packages/` and
  `server-data/storyboard-pdf-packages/` are ignored and should not be committed.
- The PM2 service is `blueprint-editor`; reload it after deploying code changes.
